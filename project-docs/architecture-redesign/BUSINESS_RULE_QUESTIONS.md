## 3. Hoshin Governance & Publishing Authority (For Implementation Phase)

### HOSHIN-Q001: ผู้มีอำนาจในการ Publish Hoshin ของแต่ละ Section/Department
* **ข้อเท็จจริงที่พบ:** ใน Legacy App 53 มีทั้ง `Department's Hoshin` และ `Section's Hoshin` แต่ไม่มีการระบุว่าใครเป็นผู้ตรวจและประกาศ
* **คำถามสำหรับ User/HR:**
  - [ ] **Option A (Centralized HR):** ฝ่ายบุคคล (HR) หรือ Corporate Planning เป็นผู้รวบรวมและกด Publish Hoshin ของทุก Section เข้าระบบ
  - [ ] **Option B (Management Level):** General Manager (GM) หรือ Section Manager เป็นผู้กด Publish Hoshin ของ Section ตนเอง
  - [ ] **Option C (Hybrid):** Section Manager ร่าง -> GM อนุมัติ -> HR กด Publish

### HOSHIN-Q002: การเปลี่ยนแปลง Hoshin ภายหลัง Objective ได้รับการอนุมัติแล้ว
* **ข้อเท็จจริงที่พบ:** ในระหว่างปีงบประมาณ อาจมีการปรับเปลี่ยนกลยุทธ์ของบริษัท
* **คำถามสำหรับ User/HR:** เมื่อมีการ Publish Hoshin Version ใหม่ในระหว่างปี ต้องการให้ระบบจัดการแบบฟอร์มที่ Approved ไปแล้วอย่างไร?
  - [ ] **Option A (Historical Lock - Recommended):** ยึดตาม Version เดิม ณ วันที่อนุมัติ และหากต้องการปรับเป้าหมายให้ใช้กระบวนการ Change Request แยก
  - [ ] **Option B (Notification & Re-open):** แจ้งเตือนหัวหน้างานและพนักงาน และเปิดสิทธิ์ให้แก้ไขเป้าหมายใหม่
